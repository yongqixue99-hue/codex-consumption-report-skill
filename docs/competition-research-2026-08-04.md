调研日期：2026-08-04（Asia/Shanghai）

## 结论

当前项目不是一个概念原型，而是已经公开、可运行并采用 Apache-2.0 的 Codex 用量分析 Skill。按技术匹配度，讯飞“数据智能分析与应用 Skill”最高。用户已决定先完成讯飞技术提交包，并确认年龄符合 AIADC 青年创新组要求；AIADC 青年创新组 / OPC 轻创作为下一阶段复用方向。任何赛事提交都不应包含真实账户数据、私人项目路径或原始会话标识。

建议排序：

1. **讯飞数据智能分析与应用 Skill**：当前主投，技术最匹配；正式上传前取得公开 Apache-2.0 基线、混合改造文件和竞赛新增成果的书面知识产权边界确认。
2. **AIADC 青年创新组 / OPC 轻创赛道**：年龄条件已确认符合，讯飞提交后复用技术成果并重点补用户验证证据。
3. **琶洲算法大赛 AI+软件应用赛**：奖金和商业曝光较好，但未排除赛前知识产权前不提交。
4. **讯飞代码智能辅助与质量保障 Skill**：当前产品匹配较弱，不应与数据赛同时分散投入。
5. **Paritok Token-Efficiency Hackathon**：时间、资格与接入成本不成比例，本届原则上放弃。

## 1. 讯飞数据智能分析与应用 Skill

官方赛题直接包含报表生成与解读、异常检测与归因、Excel/CSV 分析和多维可视化，与本项目高度一致。专家评分为稳定与可部署性 30、创新与应用价值 30、结果质量 20、技术设计 10、工程文档 5、安全合规 5；专家榜前三还需答辩。提交截止为 8 月 27 日 17:00。

现有 Skill 体积远低于 100 MB、文件数也远低于 500，但比赛包仍需：

- 增加匿名 JSON/JSONL/CSV 显式输入和完全合成的演示数据；
- 保证评委无需登录个人 Codex 账户、无需 CC Switch 数据也能完成演示；
- 在 AstronClaw 中直接返回核心摘要，并能生成离线 HTML；
- 保持 Agent Skills 兼容的 `name`、`description` frontmatter，提供一键 smoke test 和期望结果；讯飞 `version` 为可选，不为此破坏通用 Skill 规范；
- 排除 `.gitignore`、`.gitattributes`、真实报告和私有数据；
- 将无扩展名的许可文件改为允许的 `.txt` 或 `.md`，同步构建及验证脚本；
- 用确定性规则输出数据质量、峰值、集中度、缓存结构和未归属比例等可核验异常事实。

### 讯飞知识产权风险

赛题 FAQ 允许合理引用开源代码、基于开源项目二次开发，但要求注明来源、遵守许可且核心 Skill 自研内容不少于 50%；FAQ 没有公开定义该比例按功能、文件、有效代码行或 ZIP 字节计算。与此同时，官方《2026 iFLYTEK AI开发者大赛参赛协议》含有以下表述：

- 参赛作品应未被商用或授权他人，并为比赛原创；
- 对获奖作品，独占许可讯飞以修改、深化设计等方式使用；
- “除本公司与选手另有约定外”，比赛过程中独立开发的成果及相应知识产权归本公司所有；
- 讯飞及关联方取得全球、无限期、免费且可用于商业用途的使用权。

这与已发布的 Apache-2.0 仓库存在明显字面冲突，也与 FAQ 允许开源二次开发的表述存在需要赛事方解释的张力。删除仓库或改根许可证不能把已经有效授出的 Apache-2.0 版权许可描述为自动撤回；Apache-2.0 的专利许可另有自身终止条件，不应笼统概括为所有权利在任何情况下均不可撤销。公开基线 commit `94a72c6ddf8685a5b4541cb453260df0a8c39570` 的时间是 2026-08-04，晚于本届赛事开始，因此应称“赛事专项改造及本次上传前公开基线”，只有在保留的报名时间也晚于该提交时才能进一步称为“报名前公开”。提交前应向 `AICompetition@iflytek.com` 取得书面确认：

1. 上述公开基线、通用技术和第三方组件是否属于 background IP，不进入竞赛新增成果的权属或独占许可范围；
2. 基线部分、基线文件中的竞赛修改和纯竞赛新增文件分别适用什么边界，既有接收者已经取得的 Apache-2.0 权利是否不受本次提交影响；
3. FAQ 允许开源二次开发是否构成协议所称“另有约定”，与作品原创和未授权要求如何共同适用；
4. “核心 Skill 自研内容不少于 50%”的计算口径，未修改 vendor 是否排除，以及需要什么佐证；
5. 同一代码基础能否分别改造后参加两个 Skill 赛题。

泛泛的“允许参赛”回复不足以解决边界。回复应明确对应协议知识产权第 2、4 款、获奖作品独占许可条款、公开 commit、逐文件清单和最终 ZIP 哈希。该整理不替代专业法律意见。

## 2. AIADC 青年创新组 / OPC 轻创

青年创新组面向 35 周岁以下项目主体，OPC 轻创面向已有阶段成果、完成一定验证、能够现场演示但尚未成为成熟产品的项目。个人或团队均可，不限定语言、框架和操作系统。同一项目只能选择一个组别和一个赛道。

OPC 的评分是执行路径 20、阶段成果与演示 30、低成本验证 20、场景落地与产品化 20、持续发展 10。现有项目的可运行 Skill、离线报告、隐私设计、跨设备处理、测试和公开仓库都可以成为真实证据。

短板主要是外部证据，而不是代码：

- 需要 5–10 位真实目标用户访谈，至少 3 位完成可记录的试用；
- 保存问题、反馈、修复和版本变化的完整链条；
- 明确“谁使用、在什么数据条件下使用、解决什么审计问题”；
- 准备演示视频、Git 提交记录、测试结果和一页知识产权清单；
- 把产品表述从单纯的图表报告扩展为“本地优先、可审计的 AI 编程用量归因 Skill”。

官方公开规则当前未列明奖金、证书权益或报名费用，投入前应向组委会确认。宣传时也不应把该赛事描述为教育部赛事。

## 推荐的参赛定位

对外标题可以使用：

> 本地优先、可审计的 AI 编程 Token 用量归因 Skill

核心叙事：

1. 官方账户只告诉用户总量，本地日志又会因删任务、多设备和数据保留而不完整；
2. 本项目明确分开官方账户总量、本地生命周期重建和可归属项目明细；
3. 它在不上传提示词和代码的前提下，生成按日期、项目、模型、会话和时段组织的离线交互报告；
4. 每个数字都能通过数据契约、来源哈希和确定性验证复核。

避免把 API 等价估算称为实际订阅账单，也不要声称能够计算 Codex 剩余额度。
